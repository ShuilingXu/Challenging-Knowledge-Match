## 本次已修复

| 需求范围 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| 登记与会场 | 无入口会场时自动选择第一个；无效活动会跳到另一个活动 | 普通入口要求选择会场；有效会场二维码保留其会场；无效活动直接报错 |
| 联系方式鉴权 | 已登记用户缺少恢复参与入口；过期会话无法重新登记 | 可按会场与联系方式恢复参与；失效令牌回到登记流程；切换活动重置本地参与身份 |
| 工作人员权限 | 调分、人工评分、排名发奖被拦截；评分页依赖管理员题库接口 | 按活动角色开放操作；工作人员评分页可访问，题库修改和反核销/作废仍受限；工作台仅展示有成员权限的活动 |
| 积分反馈 | 人工评分拒绝负分；刷新后丢失抢答顺位 | 支持人工负分；顺位随提交记录保存，重放/刷新仍可读取 |
| 并发抢答 | 不同参与者同时 count + 1 可得到相同顺位 | 提交同一题时锁定题目行后分配顺位；并发 8 人回归得到连续且不重复的顺位 |
| 控场状态 | 进程内 Map，重启或不同实例不共享 | 控场阶段、题目、时长、开放时间存入数据库 |
| 计时 | API 返回已扣减秒数，前端再次扣减；结果耗时从公布答案开始算 | API 返回原始时长和时间基准；提交时保存从开放答题起算的耗时；到期后关闭前端答题操作 |
| 控场预览 | 选题受当前上屏题目覆盖；没有同时可见的积分表和前后题预览 | 保留待发布题目选择，补充前后题内容、媒体和当前积分表；公布答案仍针对实际开放题目 |
| 获奖确认 | “确认获奖并上屏”没有生成奖品 | 先展示当前排名和奖品供确认，再生成排名奖品并发布大屏；重复确认不重复发放同一排名奖品 |
| 数字奖品 | 参与者接口缺少兑换链接；兑换券、作废状态显示错误 | 返回和展示兑换链接/兑换码，区分待领取、已核销、已作废；奖励与抽奖机会实时刷新 |
| 抽奖会场 | 请求发送参与者自身会场，绕过入口会场核对 | 将二维码入口会场交给后端核对 |
| 批量核销 | 一次核销所有待领取奖品，多次 HTTP 调用可部分成功 | 勾选后批量核销，通过单个服务端事务完成；失败回滚 |
| 实时通知 | 提交事务前发送通知；静默吞掉 WebSocket 错误 | 提交成功后发送通知；断线重连后重新读取状态；连接/心跳错误明确显示 |
| 实时鉴权 | 参与者可订阅大屏管理消息；活动广播包含联系方式和兑换凭证；客户端可 SEND | 活动频道只发送变更通知；业务数据走已有受保护接口；禁止参与者订阅管理频道和客户端伪造服务端消息 |
| 参与端外观 | 网格背景、等宽数字、深色系统风格；头图/背景只有地址输入 | 调整为柔和配色、圆角、普通字体和活动文案；增加头图/背景上传，保留主题配置 |
| 站点页脚 | 页脚代码作为纯文本显示 | 在隔离 iframe 中呈现 HTML/脚本 |
| 素材地址 | 默认保存一小时后过期的 S3 签名 URL | 新上传素材返回稳定访问地址；访问时生成有效签名，并禁止缓存重定向 |
| 大屏模板与设备 | 注册时不能指定模板；离线设备永久显示 ONLINE；PDF 只有链接 | 注册时选择初始模板；90 秒无心跳显示离线；PDF 文件框可内嵌，Word 保留打开文件入口 |
| 页面信息 | 登录页伪造实时人数；大屏题目标题硬编码年份 | 移除虚构数值和固定年份；总览设备数量从设备接口读取 |

## 已有功能的代码核对

- 参与者独立于后台账号管理；活动、会场和联系方式具有联合唯一约束；后台访问按活动成员权限限制。
- 会场管理、登记字段新增/编辑/启停/删除、参与者姓名/ID/联系方式查询、详情和资料编辑均有界面与接口。
- 单选、多选、文本题、多媒体、部分得分、文本匹配与人工复核、题目组卷已有实现与回归覆盖。
- 活动名称、起止时间、简介、活动层级、品牌配置、终止及创建者自动加入管理员均已有实现。其他管理员通过成员管理分配。
- 系统站点名称、域名、Logo、S3 桶/接入点/凭证配置已持久化，受系统管理员权限保护。
- 奖池库存、排名范围、抽奖权重、数字/实物交付、奖品详情、单个核销、反核销与作废已有实现。
- 大屏一次性配对、设备令牌、活动/登记二维码、文本/图片/背景/文件模板、题目媒体、答案结果、积分榜、获奖名单、字号/音量/滚动设置已有实现。

## 尚待确认，未按假设修改

1. 文档要求“每场活动独立数据表”“联系方式作为主键”。目前是共表，数据库主键为 UUID，活动 + 会场 + 联系方式作为业务唯一键。已向用户确认是否要求物理分表；当前未迁移参与者表结构。
2. “抢答/排名给分”没有给出顺位与分数的对应规则。现在可记录/显示顺位，并按正确性计分、人工调分；没有自行发明顺位计分公式。
3. 当前每个奖池记录对应一种奖品；无指定奖池时可在多个奖品记录中按权重抽取，指定奖池入口只抽该记录。若“卡池”要求一个入口绑定多种独立权重奖品，需要确定奖池与奖品层级后调整模型。
