# 活动与答题逻辑检查（2026-10-02）

本次检查代码与现有集成测试，没有改变业务规则。

后续已按确认实施调整，当前行为与兼容范围请以 `ACTIVITY-WORKFLOW.md` 为准；以下保留改动前的检查记录。

## 当前实际模型

| 类型 | 身份与会场 | 题目与积分 | 抽奖 | 上下级关系 |
| --- | --- | --- | --- | --- |
| EVENT 顶层活动 | 自己保存 | 可以直接答题和计分 | 可以配置抽奖奖池并抽奖 | 可包含子活动 |
| QUIZ 答题子活动 | 自己保存，需要独立登记 | 独立题目、积分、排行榜 | 也能配置抽奖奖池并抽奖 | 继承母活动管理权限，母活动结束或终止会关闭已有子活动 |
| LOTTERY 抽奖子活动 | 复用母活动参与者、会场和报名字段 | 禁止提交答案；后台仍保留通用配置界面 | 独立奖池、次数和中奖记录 | 参与者使用母活动身份令牌；抽奖需子活动 LIVE，母活动 LIVE 或 REGISTRATION_OPEN |
| OTHER 其他子活动 | 自己保存 | 与普通答题活动基本相同 | 通用抽奖可用 | 没有对应的专门业务行为 |

## 问题

1. **母活动和子活动的职责未分开。** EVENT 是完整比赛实例，并非单纯的活动容器；QUIZ 也是完整比赛实例。OTHER 没有独立行为。抽奖能力既可以放在母活动、答题子活动的奖池里，也可以放在 LOTTERY 子活动里。导航与编辑窗口大多共用，导致用户无法从入口理解职责。
2. **答题子活动和抽奖子活动之间没有一致的身份和积分关系。** `participantScopeActivity` 仅为 LOTTERY 复用母活动。QUIZ 参与者和积分属于 QUIZ，LOTTERY 参与者和最低积分门槛使用 EVENT 的参与者与积分；QUIZ 答题所得积分不会自动汇入 EVENT，也不会自动生成抽奖机会。若想实现「先答题再摇奖」，目前没有完整链路。
3. **生命周期检查不一致。** `ensureAnsweringAllowed` 只检查本活动是否暂停、结束或终止，没有要求 LIVE，也没有检查母活动状态；因此开题后草稿可答题，母活动暂停时 QUIZ 子活动仍可接受答案和抢答。LOTTERY 的抽奖流程另有父活动状态限制。前端入口状态规则与后端执行规则并不统一。
4. **类型和归属可在已有数据后变更。** `configureActivityHierarchy` 检查层级合法性和权限，但未禁止已有参与者、题目、积分或中奖记录的活动改类型、换母活动。例如 QUIZ 改成 LOTTERY 后，身份查询会从本活动切换到母活动，原有参与者数据不再通过同一业务入口读取。此类变更需要限制或显式迁移。
5. **没有主持人统一摇奖流程。** 现有实现是「奖品与核销 → 创建抽奖奖池 → 抽奖入口 → 授予参与者抽奖机会 → 参与者打开二维码入口自行抽奖」。后台没有从符合条件的参与者中抽取中奖人的独立控场台。参与者抽奖时，后端选择奖池并发奖；指定奖池则直接使用该奖池，转盘是界面动效。
6. **抽奖子活动使用通用排行榜会误导。** 参与者列表复用母活动，但 `scoreboard` 按当前活动 ID 查参与者；因此 LOTTERY 的通用概览与排行榜数据和参与者页面不一致。LOTTERY 还可创建排名奖池，而排名发奖同样按子活动 ID 查参与者，无法从共享母活动参与者中生成正常排名名单。

## 答题模式本身

- 普通答题检查当前开放题目、倒计时、题目是否启用、活动题单和每人每题一次提交；客观题自动计分，文本未自动匹配正确时进入人工评分。
- 排名计分目前按提交顺序计算，不是按正确答案的先后另起排名。
- 抢答模式只登记每人每题一次的抢答顺序，没有答案提交和自动评分；现场评分需使用通用积分调整，没有直接关联到抢答记录的判题按钮。
- 同一题再次开题不会清除普通答案或抢答名单，目前没有「新一轮答题」概念。

## 建议的统一模型

母活动负责统一报名、人员、会场、权限和整体生命周期，展示所有环节概览。

答题子活动负责题库、普通答题/抢答、主持人开题、判题与该环节积分；参与者身份复用母活动。母活动汇总各答题环节积分，并明确抽奖资格使用哪一组积分。

摇奖子活动负责奖池、资格、主持人开始/停止摇奖、选中奖人和结果上屏；如保留参与者自行抽奖，应明确命名为「自助抽奖」，与主持人摇奖分开。

所有子活动遵循一致的母活动暂停/结束限制；有业务数据后锁定类型及归属。已有直接在母活动上的题目、积分和奖池需要兼容或迁移，不能直接隐藏入口。
