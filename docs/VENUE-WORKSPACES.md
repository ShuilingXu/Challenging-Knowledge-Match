# 会场工作区升级说明

## 工作区结构

母活动 `EVENT` 保存总题库和海龟汤稿库，不提供报名或大屏展示。独立会场 `VENUE` 属于母活动，保存自己的报名入口、登记字段、参与者、总积分、大屏配置及题库。答题、摇奖和海龟汤子活动属于会场；新建答题与摇奖环节共用本会场人员，答题环节的积分榜独立计算，得分同时计入会场总积分。

后台增加“选择会场”，活动列表按母活动、会场、子活动顺序排列。切换工作区后重新初始化题库、参与者、设置与大屏页面。

## 用户与权限

会场成员管理统一保存在会场上。在子活动的成员页面授予或移除用户，操作的也是所属会场成员。HTTP 接口、活动列表中的管理角色及 STOMP 订阅/消息授权使用同一会场归属规则。

母活动资料管理员不会自动继承到会场；仅对子活动的旧式直接授权不能绕过会场授权。系统管理员可管理所有工作区。普通账户名单接口仅返回当前授权工作区成员。

## 题目同步与随机组卷

- `GET /api/activities/{id}/questions/source`：读取当前母活动总题库，需管理员权限。
- `POST /api/activities/{id}/questions/sync`：提交 `questionIds`，只复制选中的总题库题目，适用于草稿会场或草稿答题子活动。
- 题目拥有独立 ID，并通过 `source_question_id` 记录来源；同一来源在一个活动中最多对应一道题。再次同步更新内容，保留本地排序和启用状态；未选中的题目不会被删除。
- 不覆盖已有作答或抢答记录的题目。题组引用本地题目 ID，不跨活动引用。
- 创建或更新题组可传 `randomOrder: true`。服务器在保存时随机打乱题目 ID 并持久化顺序；读取和刷新不重新随机，同一题组使用同一顺序。

## 总汤库

母活动的 `turtle_soup` 保存带独立 ID 的稿件列表。母活动支持新增和修改；会场下的草稿海龟汤环节可选择复制稿件，再独立编辑。公开内容仅发布到子活动与所属会场大屏；母活动不能展示。接口位于 `/api/activities/{id}/turtle-soup/templates` 与 `/turtle-soup/sync`。

## 数据升级

Flyway V23 增加题目来源字段与唯一索引。V24 为升级前的母活动建立命名为“原名称 - 历史会场”的工作区，把原有母活动的人员、积分、题目、奖池、中奖记录、报名字段、大屏与客户端续期会话迁入该工作区，并把原有子活动挂到其下。

历史数据保留原 ID 和相互引用，原有登记入口名称仍保留在历史会场中。原母活动题目另复制为总题库，供新的会场或子活动选择。原母活动及子活动成员转换为历史会场的显式成员。历史独立报名子活动保留原名单与积分归属。

升级不自动把混合的历史比赛记录拆成多份。历史会场用于保留原有业务上下文；新的独立会场从后台“活动管理”创建。原母活动的旧报名和大屏地址停止使用，应改发会场地址；参与者和设备升级后可能需要刷新会话或重新登录/配对。已在母活动直接开展的旧式答题，请在历史会场下创建新的答题子活动继续组织下一轮。

## 会场功能版调整（2026-10-05）

- 后台活动创建仅显示母活动、会场。会场 `features` 可选 `QUIZ`、`TURTLE_SOUP`、`LOTTERY`，创建/编辑在同一事务中保存功能配置。
- 运行记录仍保留原有 ID 和类型，避免破坏历史积分、答案、奖品和设备引用；后台不再把它们展示为独立子活动。多份旧记录可从对应功能页的“历史功能记录”选择。
- V25 为记录增加 `feature_enabled`，已有记录默认开启。不勾选会停用相应记录，保留历史数据；再次勾选复用记录。服务端 HTTP、STOMP 和业务操作检查开关。
- 母活动汤稿独立入口 `/admin/soups`；会场操作入口 `/admin/soup-control`。总稿属于母活动，不会自动覆盖已选会场副本。
- 会场海龟汤 `GET/PUT turtle-soup/playlist` 返回/配置所选稿件；`POST turtle-soup/switch` 用 `templateId`、`revision` 切换当前稿。多稿选择与切换仅在候场且未结束时允许；切换清空公开状态，屏幕回到候场，不公开汤底。
- 手册重做为 25 页、20 页配有截图，包含字段解释、操作结果和故障排查。后台手册按钮继续读取 `public/knowledge-match-user-manual.pdf`。
