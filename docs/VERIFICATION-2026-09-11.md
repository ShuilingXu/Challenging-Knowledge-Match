## 4. 异常与风险

### 4.1 【严重】后台会话频繁掉线，导致控场操作直接失败

**现象：** 后台工作台在正常使用中会突然回到登录页；掉线后所有接口返回 401，正在进行的控场操作（如「确认获奖并上屏」）失败。

**复现方法与实测结果：**

1. 用 `sysadmin` 登录，登录成功（跳转 `/app/overview`）。
2. 连续用整页地址栏方式打开 8 个后台页面。
3. **实测一轮：8/8 次跳转全部掉线**；另一轮同样的动作 8/8 次全部正常。属于间歇但可成片触发。

**根因（代码级证据）：**

- `src/main.jsx` 使用 `<StrictMode>`，`AuthProvider` 的挂载副作用因此执行两次（`src/App.jsx` 第 143 行 `refreshSession()`）。
- 每次整页加载会发出**两个并发的** `POST /api/auth/refresh`，携带同一个一次性刷新令牌。浏览器抓到的实际序列：

  ```
  NET 200 /api/auth/refresh
  NET 401 /api/auth/refresh
  NET 200 /api/auth/login
  ```

- 服务端 `server/src/main/java/com/matrixlive/security/auth/AuthService.java` 第 74 行：当刷新令牌已失效时，**吊销该令牌的整个家族**：

  ```java
  for (RefreshToken token : refreshTokens.findByFamilyIdAndRevokedAtIsNull(existing.getFamilyId())) token.revoke(null);
  ...
  throw new DomainException(HttpStatus.UNAUTHORIZED, "Refresh token has expired or was revoked");
  ```

- 于是两个并发刷新中落败的那个会吊销家族 → `AuthProvider` 捕获失败 → `clearSession()` → 用户被登出。

**影响：** 这是面向现场活动的高可靠场景（需求写明「需要高并发高可用」）。现场工作人员在比赛进行中被登出、控场按钮失效，属于业务不可接受的中断。

**规避方式（本轮实测有效）：** 使用站内侧栏导航（SPA 内部跳转，不触发整页重载、不重挂 `AuthProvider`）时不再掉线。日志中也出现过同一页面两次刷新都返回 200 的情况，说明是竞态而非必然失败。

**注：** 本轮**没有**修改任何代码；是否修复由用户决定。

### 4.2 【中】控制台持续出现 401 噪声

后台每个页面几乎都会打印 `Failed to load resource: the server responded with a status of 401 (Unauthorized)`（来源为 `/api/auth/refresh`）。在无工作人员登录态的场景（大屏页）同样出现。它本身不阻塞功能，但与 4.1 同源，会让真实故障被噪声淹没。

### 4.3 【中】`vite preview` 模式下 WebSocket 通道不可用

- 第一轮用 `vite dev` 时实时通道正常：控场开题后，参与者页面**未刷新**即出现题目，大屏也实时切换模板。
- 第二轮用 `vite preview` 时控制台出现 `net::ERR_CONNECTION_REFUSED`，实时推送未能确认（本轮改用了整页刷新读取状态）。

这不是业务代码缺陷，而是**「用预览服务器代替开发服务器」这一临时做法导致的**：`vite.config.js` 中 `/ws` 的代理只在 dev server 生效。生产用 nginx（`deploy/match.soyorin.love.conf`）部署时需确认 `/ws` 已正确反代。

### 4.4 【低】仓库内残留浏览器档案导致 `vite dev` 无法启动

- 验证中 `npm run dev` 失败并退出：

  ```
  Error: EBUSY: resource busy or locked, watch '...\test-assets\edge-qa-profile\Default\Network\Cookies'
  ```

- `test-assets/edge-qa-profile/` 是一份被放在仓库里的浏览器用户档案（未被 git 跟踪）。vite 的文件监听扫描到被占用的文件后直接崩掉，整个开发服务器起不来。
- 建议：把该目录移到仓库外，或加入忽略；否则任何依赖 `vite dev` 的人都会随机遇到启动失败。

### 4.5 【低】`docs/RUN.md` 的端口说明与实际不符

`docs/RUN.md` 写「Run `npm install` once, then `npm run dev`. The UI is available at `http://127.0.0.1:4173`」。实测：

- `npm run dev` 实际监听 **5173**（vite dev 默认），且只绑定 IPv6，`http://127.0.0.1:5173` 连接被拒，须用 `http://localhost:5173`。
- **4173** 是 `vite preview` 的默认端口，不是 dev 的。
- 另：文档里的 API 地址 `http://127.0.0.1:8080` 正常可用。

### 4.6 【低】参与端顶部视觉元素在 390px 下轻微重叠

新主题下，参与端顶部 sticky 区域的小 Logo/徽标与「相聚在此刻 / 一起挑战 / 领取你的惊喜」文案发生重叠（截图 `93-fresh-answer.png` 顶部）。不影响功能，属视觉细节。

### 4.7 【观察】参与端会话存在 `sessionStorage`，关闭浏览器即丢失

参与者令牌与身份存在 `sessionStorage`。浏览器重启后需通过「查询已登记的参与信息」恢复（本轮实测可恢复）。行为与需求「联系方式作为主键识别用户」一致，这里只作为现场操作提醒：同一台设备重开浏览器不会自动续上参与身份。
