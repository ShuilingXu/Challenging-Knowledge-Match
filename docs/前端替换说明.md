# 前端文件替换说明

适用版本：2026 年 10 月 6 日当前代码与新版图文操作手册。

## 先确认部署方式

仓库的生产脚本将 match.soyorin.love 的前端放在：

```text
/opt/1panel/www/sites/match.soyorin.love/index/
```

OpenResty 从这个目录提供网页，后端由 `knowledge-match.service` 运行在本机 8082 端口。本说明介绍前端静态文件的替换步骤。海龟汤自动分页与远程播放控制需要配套更新后端 JAR，具体见《海龟汤自动翻页更新说明》。无需为此修改域名证书或反向代理。若你已经调整过服务器配置，请以 1Panel 网站设置里当前的“运行目录”为准，不要把文件传到未知目录。

前端包应展开为：

```text
index/
  index.html
  assets/
    index-新的版本编号.js
    index-新的版本编号.css
  knowledge-match-user-manual.pdf
```

**把压缩包里的内容放进网站运行目录。不要形成 `index/dist/index.html` 或 `index/frontend/index.html`。**

新版功能需要配套后端。前端只能显示和调用已有接口；会场功能、题库和题组同步需要当前后端及其数据库迁移，其中题组同步包含 V26 迁移。如果服务器尚未更新到这些功能，先按完整部署流程更新后端，单独复制前端不能补齐接口。

## 方法一 使用 1Panel 文件管理

1. 打开 1Panel，进入网站列表，找到 `match.soyorin.love`，查看其运行目录。按现有配置应为上面的 `index` 目录。
2. 在文件管理中把现有 `index` 目录完整复制一份，例如 `index-backup-20261005-2300`。复制成功后检查备份里有旧 `index.html`、`assets` 和手册。
3. 上传 `output/frontend-latest.zip` 到网站目录之外的临时位置，解压到一个新文件夹。检查解压文件夹第一层就有 `index.html`，而不是只有 `dist` 文件夹。
4. 把新文件夹里的 **assets 文件夹内文件** 复制到网站的 `index/assets`，同名提示选择覆盖。保留已有旧版本的 assets 文件，方便已打开的旧页面继续加载和需要时回退。
5. 将新的 `knowledge-match-user-manual.pdf` 复制到网站 `index` 目录并覆盖旧手册。
6. **最后**将新的 `index.html` 复制到网站 `index` 目录，覆盖原文件。这样首页引用新资源前，资源已经到位。
7. 文件管理里核对三个部分齐全。静态文件通常无需重启后端或 OpenResty。
8. 电脑按 `Ctrl + F5` 强制刷新；手机关闭旧页后重新打开。若启用了 CDN 或页面缓存，刷新其缓存。

## 方法二 使用服务器终端

先把压缩包上传到 `/opt/challenging-knowledge-match/frontend-latest.zip`。下面命令在 Linux 服务器上执行，不是在你电脑的 PowerShell 中执行。

```bash
set -euo pipefail
site_root=/opt/1panel/www/sites/match.soyorin.love/index
release_stamp=$(date +%Y%m%d-%H%M%S)
backup_root="${site_root}-backup-${release_stamp}"
release_root="/opt/challenging-knowledge-match/frontend-release-${release_stamp}"
package_path=/opt/challenging-knowledge-match/frontend-latest.zip

# 先确认现有站点，备份后再写新文件
test -f "$site_root/index.html"
test -f "$package_path"
cp -a "$site_root" "$backup_root"
mkdir -p "$release_root"
unzip -q "$package_path" -d "$release_root"
test -f "$release_root/index.html"
test -d "$release_root/assets"
test -f "$release_root/knowledge-match-user-manual.pdf"

# 先准备资源和手册，保留旧资源文件
mkdir -p "$site_root/assets"
cp -a "$release_root/assets/." "$site_root/assets/"
cp "$release_root/knowledge-match-user-manual.pdf" "$site_root/knowledge-match-user-manual.pdf"

# 首页最后替换
cp "$release_root/index.html" "$site_root/index.html.new"
mv "$site_root/index.html.new" "$site_root/index.html"
printf '备份位置：%s\n' "$backup_root"
```

以上命令面向本次压缩包的三个内容部分。以后增加其他 public 静态文件时，也要在替换 `index.html` 前复制对应文件。

## 替换后的核对

- 打开 `https://match.soyorin.love/login`，正常登录、选会场。
- 直接打开内部路径再刷新，例如 `/admin/questions`。应正常显示页面；若 404，检查现有 SPA 回退配置是否保留。
- 题库显示十题分页，可以按答案筛选；草稿会场能打开“选择总题组”。用测试会场核对，避免同步覆盖正式资料。
- 打开参与者入口，列表有开放会场；手机底部导航和单一会场自动选择正常。
- 在后台打开“用户操作手册”，确认是新版完整图文内容。
- 已配对大屏核对显示与主持人状态一致。已有观众页可以在一轮结束后统一刷新，避免正在答题时刷新影响体验。

## 页面出错如何回退

1. 先检查新资源是否上传完整、目录是否多套了一层、浏览器是否仍缓存旧页面。
2. 需要回退时，把备份中的 `index.html` 和旧手册复制回运行目录。因为上面保留了旧 assets，旧首页还能找到旧资源。
3. 若目录或权限另有改动，由维护人员对照完整备份恢复；不要删除数据库、媒体文件或服务器环境配置。
4. 强制刷新后再次检查登录和内部路径。旧文件的正确来源是本次替换前的备份。

## 以后如何重新生成前端包

在 Windows 电脑的项目根目录打开 PowerShell：

```powershell
npm ci
npm test
npm run build
Compress-Archive -Path .\dist\* -DestinationPath .\output\frontend-latest.zip -Force
```

`npm run build` 将源代码转换成 `dist` 里的浏览器文件，同时复制 `public` 里的新版手册。不要把 `src/App.jsx`、`node_modules` 或整个源码文件夹直接作为静态网页上传。前端包生成后，再按上面的资源优先、首页最后顺序替换。
