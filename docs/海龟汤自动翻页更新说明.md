# 海龟汤自动翻页更新说明

此次更新需要前端和后端一起更新，未部署到线上。

## 现场使用

展示汤面后默认自动分页。新公开线索会定位到对应内容；揭晓后汤底在独立大区域播放。短内容完整显示，长内容按实际屏幕尺寸分页，页底显示页码和播放进度。

主持人端页面顶部“大屏播放控制”提供暂停、继续、上一页、下一页、从头播放、加速和减速。每次加减速调整 3 秒，到边界时停在 8 或 40 秒；显示的“每页几秒”就是实际翻页间隔，长文本不会额外延时。调速保留当前页和暂停状态。上一页和下一页作用于各个分区，并自动暂停，方便讲解。新公开线索和揭晓会恢复自动播放；需要讲解时可再次暂停。

控制只影响当前会场。刷新或新接入的屏幕会读取已有播放状态。不同屏幕和预览的尺寸、字号不同，分页数量也可能不同，以现场大屏为准。

屏幕高度较低时优先显示当前内容：未公开线索时显示汤面，有线索时显示线索，揭晓后显示汤底，避免同时显示多个分区导致文字区域过小。

## 更新文件

- `output/frontend-latest.zip`：前端静态文件及新版完整手册。
- `output/backend-latest.jar`：本次后端构建，需要 Java 21。
- `output/海龟汤自动翻页更新包.zip`：包含上述两份文件、简明手册和更新说明。

部署前先备份当前前端目录、后端 JAR 和数据库。安排在活动结束或维护时间进行。

1. 在服务器执行 `systemctl cat knowledge-match.service`，确认启动方式。仓库现有配置先运行 `/opt/challenging-knowledge-match/deploy/run-api.sh`，该脚本使用 `/opt/challenging-knowledge-match/server/target/knowledge-match-api-0.1.0.jar`。如果实际配置不同，继续查看启动脚本确认 JAR 路径，以服务器配置为准。
2. 备份该 JAR；将新 `backend-latest.jar` 上传到临时位置，再替换服务实际使用的 JAR，保留原属主和权限。
3. 执行 `systemctl restart knowledge-match.service`，用 `systemctl status knowledge-match.service` 和 `journalctl -u knowledge-match.service -n 100 --no-pager` 检查启动结果。若启动失败，恢复备份 JAR 并重启。
4. 后端正常后，按《前端替换说明》更新前端资源和手册，最后替换首页。
5. 刷新主持人页面和大屏，用测试会场验证自动翻页、暂停、继续、新线索和揭晓。

不需要新增数据库字段或配置：播放状态随原有海龟汤状态保存。服务仍按现有数据库迁移规则启动；请勿删除数据库、上传素材或环境配置。

## 验证

本次前端 51 项测试、后端海龟汤 7 项集成测试通过，生产构建成功。本地浏览器验证了实际大屏联动、自动播放、暂停刷新保持、从头播放、新线索定位及窄屏显示；长内容验证到 8000 字汤底。
